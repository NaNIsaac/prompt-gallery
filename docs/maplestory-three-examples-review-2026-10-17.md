# 메이플스토리 중단 작업 복원 및 3종 예시 검토

2026-10-17 (Asia/Seoul). 사용자는 인물 전용 메이플스토리 변환을 반려동물·풍경용으로 확장한 뒤, 기존 인물도 새 범용 문구로 다시 생성하고 인물·반려동물·풍경 결과 3개를 모두 배포된 웹에 넣도록 요청했다. 중단된 것으로 보고된 작업을 실제 파일·Git·PR·공개 카탈로그와 대조해 복원했다.

## 재개 시 확인한 상태

| 요구사항 | 확인된 상태와 근거 |
|---|---|

| 범용 문구 작성 및 동물·풍경 테스트 | 로컬·PR 단계 완료. 브랜치 `codex/expand-maplestory-photo-inputs`, PR #16에 문구·기록이 있었고 PNG 4개가 존재했다. 이전 기록과 SHA-256을 대조했다. |
| 범용 문구의 실제 웹 배포 | 미완료. PR #16은 미병합이며 공개 항목의 사진 조건은 여전히 `portrait`였다. |
| 기존 인물 원본의 범용 문구 재생성 | 미완료. 기존 기록에는 동물·풍경 두 테스트만 있었다. |

단순히 마지막 CI 성공을 배포 완료로 해석하지 않았다. 중단 이후 main에 반영된 발로란트·X선 필름 항목을 병합하고 문서 목차 충돌은 양쪽 링크를 모두 보존해 해결했다. 다른 항목을 삭제하거나 이전 버전으로 덮어쓰지 않았다.

## 이번에 수행한 작업

기존 가상 인물의 PNG 원본 한 장에 현재 공개 범용 프롬프트 전체만 전달해 내장 `image_gen.imagegen`으로 새 결과를 생성했다. 이전 인물 결과를 스타일 참고로 넣거나 추가 지시를 붙이지 않았다. 강아지·풍경은 중단 이전 생성 PNG를 해시 확인 후 재사용했다. 세 사례의 실제 입력과 원본·결과·공개 파일의 SHA-256은 [생성 기록](image-generation-2026-10-17-maplestory-three-examples.json)에 보관한다.

기존 항목 ID·공유 URL·순서를 유지하면서 `examples`에 인물·반려동물·풍경을 등록했다. 대표 이미지는 새 인물 결과로 교체했다. 공개 상세에서 예시를 선택하면 해당 결과·첨부 원본·설명·확대 및 다운로드 대상이 함께 바뀌며, 복사되는 범용 프롬프트는 동일하다. 다른 항목은 기존 단일 예시 표시를 유지한다. 이미지마다 별도 카드를 만들어 동일 프롬프트를 중복 등록하지 않았다.

결과 세 장은 무손실 WebP로 변환하고 PNG와 디코딩된 픽셀이 일치함을 확인했다. 새 동물·풍경 첨부 원본은 WebP 품질 92로 변환했으며 기존 인물 첨부 원본은 변경하지 않았다. 대표 썸네일만 비율을 유지해 560×315로 축소했다.

## 이미지 수동 검토와 한계

- 인물: 갈색 머리·둥근 안경·청재킷·노란 상의·크림색 바지·빨간 운동화가 SD 캐릭터로 반영됐다. 달팽이·버섯 캐릭터가 배경에 추가됐고 원경은 흐려져, 프롬프트의 또렷한 도트·흐림 회피 조건이 완전히 준수되지는 않았다.
- 반려동물: 코기의 큰 귀·삼색 털·짧은 다리·청록 하네스·앉은 자세와 거실의 소파·러그가 유지됐다. 사람이 추가되지 않았다. 공·방석·봉제 장난감과 발판·사다리가 추가됐다.
- 풍경: 왼쪽 돌 아치교와 오른쪽 정자, 계곡·산·소나무를 알아볼 수 있는 게임 맵으로 변환됐다. 사람·동물·몬스터·닉네임은 추가되지 않았다. 발판·사다리·폭포와 가을 색감이 추가·재해석됐다.

실제 메이플스토리 리소스나 정확한 HUD가 아니며 사진의 얼굴·배치·작은 소품을 완전히 동일하게 재현하는 기능이 아니다. 원본들은 모두 가상 생성 사진이다. 사진별 한계를 각 공개 예시 설명에 표시한다. 복수 대상·사물 단독 입력은 이번에 추가 생성 테스트하지 않았다.

## 검증 범위

데이터 검증은 예시 라벨·크기·첨부 원본·파일 경로와 첫 예시의 대표 이미지 일치를 확인한다. 자산 검사도 모든 예시의 결과·원본을 포함해 서로 다른 원본과 결과가 연결되고 사용하지 않는 이미지가 공개 폴더에 남지 않는지 검사한다.

브라우저 검사는 데스크톱·모바일에서 세 예시 선택, 해당 원본 확대, 결과 확대·다운로드 링크, 설명 전환, 동일 프롬프트 복사, 새로고침 후 기본 예시와 단일 예시 항목 복귀를 확인한다. 배포 완료 여부는 PR 병합 및 main의 Pages 작업 성공 후 공개 사이트에서 별도로 확인한다.

최종 코드의 `npm run check`에서 단위·데이터 검사 14개, 공유 페이지 27개 빌드, 데스크톱·모바일 Chromium 검사 12개가 모두 통과했다. 로컬 빌드에 대한 별도 브라우저 검증에서도 일곱 공개 이미지의 SHA-256, 두 화면 크기의 세 예시·원본 로딩·복사·공유 링크가 일치했고 처리되지 않은 JavaScript 오류가 없었다. `node --check app.js`, `node --check scripts/validate.mjs`, `git diff --check`도 통과했다.

이후 main에 추가된 카트라이더를 반영한 최종 병합 상태에서도 전체 검증을 다시 실행해 단위·데이터 검사 14개, 공유 페이지 28개 빌드, 데스크톱·모바일 검사 12개가 모두 통과했다. 최신 main의 다른 27개 카탈로그 항목이 그대로임을 비교 확인했고, 데스크톱 1280×900·모바일 393×851 화면의 선택 버튼·결과·첨부 원본 영역과 가로 넘침 여부를 직접 검토했다.
