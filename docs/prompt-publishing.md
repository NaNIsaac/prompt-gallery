# 프롬프트 등록 원칙

## 원문과 예시를 구분한다

사용자가 제공한 프롬프트는 요청이 없는 한 의미·표현·자리표시자·오탈자를 임의로 고치지 않는다. 파일의 줄바꿈 통일은 가능하다. 사용 편의를 위한 사진 조건과 자리표시자 설명은 `inputLabel`·`usage`에 쓴다.

결과를 테스트할 때는 해당 프롬프트와 공개할 원본 이미지의 연결을 보존한다. 도구에 추가 조건을 붙이거나 원문을 수정했다면 실제 도구 입력을 기록하고 `exampleNote`로 차이를 알린다. 다른 지시로 만든 예시를 원문만 적용한 결과로 표시하지 않는다.

## 원본 → 결과 → 검토 → 등록

1. 프롬프트에 맞는 원본 이미지를 준비한다. 새 AI 원본을 만들었다면 그 사실과 원본 생성 프롬프트를 기록한다.
2. 해당 원본 한 장과 테스트할 프롬프트를 이미지 생성 도구에 전달한다. 여러 항목의 원본을 혼동하지 않는다.
3. 원본과 결과를 눈으로 비교한다. 인물·피사체 특징, 구도, 색·스타일, 텍스트와 금지 조건을 확인한다.
4. 요청이 충분히 반영되지 않았으면 재시도하거나 한계를 공개 설명에 기록한다. 미반영 조건이 있는 결과를 완전 준수 예시로 설명하지 않는다.
5. 최종 원본·결과·썸네일을 프로젝트에 저장하고 카탈로그와 생성 기록을 추가한다.
6. `npm run check` 후 작업 브랜치의 PR로 게시한다.

이미지 생성은 콘텐츠 제작 단계다. CI 실행마다 이미지를 다시 생성하지 않는다. API 키나 외부 이미지 생성 계정도 CI에 필요하지 않다.

## 파일과 데이터

각 항목은 `assets/images/<id>.reference.webp`, `<id>.webp`, `<id>.thumb.webp`를 사용한다. 원본을 자르거나 보정해 피사체가 달라지지 않도록 한다. 썸네일은 결과의 비율을 유지해 축소한다. 원본 PNG가 생성 도구의 기본 위치에 있어도 공개 사이트가 참조하는 자산은 반드시 저장소 안에 둔다.

`data/prompts.json`의 스키마와 예시는 [루트 README](../README.md#프롬프트-추가)를 따른다.

- `id`는 고유한 영문 소문자·숫자·하이픈 식별자이며 공개 후 함부로 바꾸지 않는다. 상세 공유 URL에 사용된다.
- `width`·`height`는 실제 결과 이미지 크기다.
- `referenceImages`는 최소 1개이며, 현재 검증은 항목별로 서로 다른 원본을 요구한다.
- AI 원본과 결과임을 사용 안내나 예시 설명에 표시한다.
- 한 프롬프트에 여러 변환 사례를 공개하려면 선택 항목 `examples`를 사용한다. 각 예시에 고유한 `label`, 결과 `image`, 실제 `width`·`height`, 해당 결과에 입력한 `referenceImages`, 생성 조건과 한계를 설명하는 `note`를 넣는다. 예시는 최소 두 개이며 첫 예시는 카드의 `image`·크기·`referenceImages`와 일치해야 한다. 썸네일과 공유 미리보기는 첫 예시를 사용한다. 서로 다른 결과의 원본을 최상위 `referenceImages`에 섞지 않는다. 상세 선택 시 결과·원본·설명·확대·다운로드 대상을 함께 전환한다.
- `sourceUrl`에는 실제 출처를 넣는다. 외부 스타일 참고 자료는 `inspirationUrl`로 구분한다.
- 이미지 경로는 로컬 `assets/` 아래를 사용한다. 사용하지 않는 이미지를 이 공개 폴더에 남기지 않는다.

## 신규는 위로, 기존 순서는 유지

기본 정렬은 `order` 오름차순이다. 배열에 넣은 위치나 생성 날짜로 자동 정렬되지 않는다.

현재 최솟값이 `m`이고 새 항목이 `N`개라면 요청 순서대로 `m−N`부터 `m−1`까지 부여한다. 예를 들어 최솟값이 `-6`일 때 3개를 추가하면 새 항목은 `-9`, `-8`, `-7`이다. 기존 항목의 `order`는 수정하지 않는다. 여러 PR이 동시에 등록한다면 병합 전에 최신 `main`을 반영해 값의 충돌과 신규 배치를 재확인한다.

그 결과 신규 묶음이 가장 위에 오고 기존 항목끼리의 상대 순서는 유지된다. 제목순 정렬은 사용자가 명시적으로 선택했을 때만 적용된다.

## 생성 기록

`docs/image-generation-YYYY-MM-DD.json`에 다음을 보관한다. 같은 날 추가 작업이 있으면 기존 기록을 지우지 말고 이어 쓰거나 구별되는 새 파일로 기록한다.

- 항목 ID, 생성일, 실제 사용 도구
- 원본 생성 프롬프트와 최종 변환 프롬프트
- 재시도의 추가 지시와 최초 요청과의 차이
- 원본·결과·썸네일 경로, 실제 크기, SHA-256
- 필요한 경우 생성 도구가 반환한 원본 파일명과 해시

내용 검토는 별도 Markdown 기록이나 `exampleNote`에 남긴다. 이전 예시와 프롬프트를 바꾸면 과거의 생성 사실을 덮어쓰지 않고 새 이력을 추가한다. 공개하지 않을 개인 정보나 인증 정보를 기록하지 않는다.
