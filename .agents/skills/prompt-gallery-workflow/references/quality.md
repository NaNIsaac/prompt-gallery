# 제작·테스트에서 유지할 기준

## 원본과 문구

- 사용자가 구체적인 원문을 줬으면 그대로 시험한다. 새 문구를 설계하는 요청이면 원하는 변환과 보존할 요소를 먼저 정리한다.
- 인물은 연령·머리·안경·옷·식별 특징, 동물은 종·체형·귀·꼬리·무늬 위치·착용물, 풍경은 시점·주요 지형·건축물·길·물길의 관계를 기준으로 삼는다. 사람 없는 사진에 사용자 얼굴을 만들지 않는다.
- 대상 작품의 스타일은 선·비례·채색·재질·디테일 수준처럼 결과에서 판별할 수 있게 쓴다. 원작 캐릭터를 추가한다면 알아볼 수 있는 특징과 사진 대상과의 상호작용을 명확히 한다.
- 장면은 사용자 요청에 맞춰 정한다. 범용 문구라면 보존 조건을 고정하고 장소·사건·행동은 사진의 시각적 단서에 맞춰 선택하도록 한다. 특정 과자·분필·곤충처럼 한 시험에서 잘 나온 소재를 보편 규칙으로 승격하지 않는다. 사용자가 특정 장면을 원했다면 그 장면을 유지한다.
- 프롬프트로 사건 대상을 요구하면서 모든 추가 사물·동물을 금지하는 식의 상충 조건을 점검한다. 과거 문구에 모순이 있어 새로 수정하면 버전을 올리고, 기존 결과를 새 문구의 시험 결과로 바꾸어 설명하지 않는다.

## 시험과 수정

1. 사용자의 사진 또는 사진별로 새로 만든 가상 원본을 준비한다. 가상임을 명시하고 생성 문구를 저장한다. 이 대화에서 보지 않은 로컬 이미지는 도구로 먼저 확인한다.
2. 변환할 사진 한 장과 시험할 문구를 연결해 전달한다. 비교용 여러 원본이나 작품 참고 자료를 동시에 넣었다면 실제 입력을 모두 기록한다.
3. 원본과 결과를 비교한다. 식별 특징, 대상 수, 전체 구도, 스타일 통일, 구체적인 행동, 손발과 소품 연결, 문자·로고 등 금지 조건을 본다. 예쁜 결과만으로 지시 준수를 판단하지 않는다.
4. 수정까지 요청된 작업이면 실패한 요소만 겨냥해 문구를 보완하고 다시 확인한다. 새로운 문구는 새 버전으로 남긴다. 같은 문구로 시험만 요청받았다면 원문을 유지하고 한계를 보고한다. 다른 사진에 같은 최종 문구를 적용할 때는 사진별 장면 지시를 덧붙이지 않는다.
5. 범용 입력은 서로 다른 유형으로 확인한다. 한 장의 성공으로 모든 연령·동물 무늬·장소에서 같은 수준을 보장하지 않는다. 장면 다양성을 시험한다면 실제 나온 결과로 평가하고 매 실행의 차이를 보장한다고 쓰지 않는다.

## 기록과 공개 설명

실제 도구·모드·문구·참조 파일·추가 지시·시도 결과·출력 파일을 연결한다. 중단·차단·연결 오류와 성공을 구별한다. 변경 전 문구와 결과를 덮어써 생성 사실을 잃지 않는다.

예시별 설명에는 AI 가상 원본 여부, 같은 공개 문구만 사용했는지, 실제로 유지된 특징과 눈에 보이는 한계를 적는다. 후편집을 했다면 그 결과를 원래 문구만의 결과로 표시하지 않는다.

짱구 테스트에서 유효했던 것은 피드백→범용 문구→다른 입력 시험→한계 공개의 과정이다. 그 작품·장면·가상 인물 자체는 새 작업의 필수 조건이 아니다.
