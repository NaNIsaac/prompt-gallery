# 중간 검토와 채팅 선택지

## 결과를 먼저 보여준다

실제 원본과 변환 결과, 적용한 문구·버전, 관찰한 장단점을 제시한 뒤 질문한다. 질문 도구로 이미지 첨부를 요구하지 않는다. 현재 브랜치·작업 공간을 표시하고 다음처럼 이유와 다음 단계를 분명히 안내한다.

> 현재는 결과 검토 단계입니다. 결과 확정을 기다리고 있어 PR은 아직 만들지 않았습니다. ‘결과 확정·PR 제출’을 선택하면 등록·검증 후 Draft PR을 만듭니다. ‘수정’은 피드백을 반영하고, ‘다른 사진으로 테스트’는 같은 문구를 다른 원본에 적용합니다.

게시 요청이나 기존 PR이 있으면 실제 상태에 맞게 문구를 바꾼다. 승인된 예시와 이미 받은 요청을 기록에서 확인하여 같은 결정을 다시 묻지 않는다. 사용자에게 중간 검토 없이 결과 선택까지 맡은 경우에도 실제 결과·한계와 수행한 작업을 보고한다.

## 네이티브 질문 도구 우선

- 실행 환경에 노출된 도구와 모드 제한을 확인한다. 사용할 수 있으면 `request_user_input_async`처럼 채팅 선택지를 제공하는 질문 도구를 우선 사용한다. `request_user_input`은 실제 도구 설명과 모드가 허용할 때만 사용한다. 스킬 자체가 버튼 UI나 없는 도구를 새로 제공한다고 주장하지 않는다.
- 질문은 한 번에 하나, 짧고 구체적으로 묻는다. 기본 선택지는 **결과 확정·PR 제출 / 수정 / 다른 사진으로 테스트**이며, 실제 요청에 맞춰 바꿀 수 있다. 명시적인 테스트 전용·PR 제외 제한이 있으면 첫 항목을 "테스트 결과 확정·보관"으로 바꾸어 제출을 유도하지 않는다. 자유 입력을 허용하고 UI가 자동으로 제공하는 자유 입력 항목을 중복 추가하지 않는다. "여기서 보관"이라는 자유 응답도 존중한다.
- 예: `request_user_input_async({ questions: [{ title: '표시한 v1 결과를 어떻게 이어갈까요?', options: ['결과 확정·PR 제출', '수정', '다른 사진으로 테스트'] }] })`. 이 도구가 실제로 제공되는 환경에서만 호출한다.
- 네이티브 도구를 쓸 수 없으면 최종 응답에서 같은 세 항목을 번호 목록으로 제공하고 번호 또는 자유 입력으로 답할 수 있다고 안내한다. 텍스트를 클릭 가능한 버튼이라고 설명하거나 UI 지시문을 임의로 만들지 않는다.

## 응답과 재개

- **결과 확정·PR 제출:** 표시한 결과와 문구를 확정하고 게시 지침의 등록·검증·Draft PR을 진행한다. 이 선택만으로 담당자 병합·배포를 허용하지 않는다. 제출 제외 제한이 있는 세션에서는 이 제출 항목을 기본으로 제시하지 않는다.
- **수정:** 구체적인 피드백이 있으면 바로 반영한다. "수정"만 선택하면 필요한 변경 한 가지만 질문하고, 다음 버전 결과를 보여준다.
- **다른 사진으로 테스트:** 이미 지정한 입력 유형을 따르고, 없으면 목적에 맞는 가상 원본을 정해 같은 문구로 시험한다. 바꾼 문구를 몰래 적용하지 않는다.
- **결과 확정 또는 "좋다"만 응답:** 시각 결과 확정으로 기록한다. 제출 의사가 불명확할 때만 PR 제출 여부를 질문한다. "ㄱㄱ"는 직전 제안·요청 범위를 따라 해석하며 새 배포 승인을 임의로 추가하지 않는다.
- 비동기 질문 뒤에는 검토 기록 보완 등 응답에 의존하지 않는 일만 계속할 수 있다. 명시적 응답 전에는 등록·push·PR 같은 선택에 의존하는 단계를 진행하지 않는다. 미리 선택된 항목·무응답·시간 경과는 응답이 아니다. 검토 자료를 보존하고 **검토 대기**로 넘긴다. 폴링하며 무기한 기다리지 않는다.
- 작업 공간의 기존 `review.md` 등에 검토 대상 문구·결과 버전과 경로, 현재 단계, 사용자 응답, 다음 행동을 남긴다. 재개할 때 같은 브랜치·결과와 연결하고 아직 승인되지 않은 새 버전을 확정본으로 바꾸지 않는다.
